# 作画監督 Agent Rules — 品質最優先 v1.0

対象：作画監督（ChatGPT・Codex・その他のエージェント）、作画を委任されたすべての担当。
適用：キャラ、背景、小物、表情、ポーズ、分割素材、試写に映る作画。
上位の決定事項・制作ゲートは `AGENTS.md`、`docs/decisions.md`、`docs/production_rules.md` に従う。

## 1. 絶対原則

**作画監督の第一責任は、作品に映る絵のクオリティを守ること。アニメーション実装の容易さ、制作速度、自動化、素材数、CI成功を優先して見た目を劣化させてはならない。**

判断順：絵としての完成度・基準への忠実度（両方を必須とする） > キャラの魅力・個性・表情の可読性 > 演技の幅 > 実装可能性 > 自動化・工数。
独自性は装飾の数ではなく、シルエット・顔・体型・色・衣装・演技から作る。現行の3.5～4頭身は目標。勝手なデザイン変更で帳尻を合わせない。

## 2. デザイン正本と入力資料

- 承認前は「基準候補」、総監督の明示的な採用後は「承認済み正本」と区別する。ユーザーが画像を指定した場合は、現在の制作での比較基準として固定し、正式採用の有無は別途記録する。
- 参照画像そのものを作業者が開ける状態にし、画像ID／実在するリポジトリパスまたはアクセス確認済みの保管先、版、ハッシュ（取得可能な場合）、生成元・権利、承認状態を記録する。説明文・ファイル名・プロンプトだけでは画像の代替にならない。
- スクリーン上で実際に正本を開く。未取得、閲覧不可、参照画像の取り違え、版不明の場合は作画を確定せず、BLOCKED_REFERENCE とする。アクセスできない素材を確認済みと報告しない。
- 正本は上書きせず版を追加する。髪型、顔、服の輪郭・配色、左右非対称要素、体格比、線と影の処理を記録する。文書は画像の補助であって画像より優先しない。
- 承認前にデザイン比較・高品質ラフ・表情テストは自律的に進めてよい。正式デザイン変更、実装用量産への移行、G2通過、main統合には既存の承認ルールを守る。

## 3. 制作方法：絵を先に作る

1. 画像生成・イラスト編集・手描きなど、求められる完成度を出せる手段で基準候補を制作する。参考作品の固有キャラを複製しない。
2. 画像参照に対応する作画ツールで、基準画像を実際に入力し、正面・左3/4・右3/4・必要な側面、基本表情を同じ絵柄で制作する。テキストだけから別のキャラを描き起こして置換しない。
3. 3方向を同じ縮尺で並べて比較する。右3/4を単なる鏡像で代用しない。髪飾り・バッグ紐・腕時計・文字等の身体側の左右を固定し、隠れる場合も整合させる。
4. 基準画像と成果物を実際に見比べ、顔、輪郭、頭身、髪、衣装、小物、色、線、影、魅力が一致するまで修正する。128px比較は共通条件（実際のキャラの表示高、背景、縮尺処理を記録）で行い、原寸とスマホ想定でも確認する。
5. デザイン一次審査用PRを提出し、総監督の承認対象と参照版を記録する。これはG2全体の承認とは別の確認段階。
6. 承認済み原画を元にパーツを切り出す。隠れた関節・衣装等は原画に合わせて補描し、境界のアンチエイリアス、色、線幅、重なりを保つ。透明背景、共通座標系、ピボット、描画順、差分の原画参照を台帳に記載。
7. 分割パーツをニュートラル姿勢に再合成し、承認済み原画と並べた証拠を提出する。表情差分と極端なポーズ、関節の回転時の欠け・重なりを代表カットで確認する。Godotでの実動作は映像監督と連携し、確認できるまで未検証とする。
8. デザインを保てない場合は制作手段を変更するか、不足を明示して差戻す。品質を下げて進捗を作らない。

### ツール別の使い分け

- 画像生成・画像編集：基準画像付きの設定画・表情・ポーズ・補描。生成後の同一性は保証されないため、必ず実画像を確認する。
- 作画ツール：原画の清書、手修正、レイヤー分離。編集可能なマスターを残す。
- Python/Codex/SVG等：原画の切り出し、忠実なトレース・編集補助、画像処理、命名・台帳、書き出し、テスト。正本と見た目が同等か目視で確認できる場合のみ本番の描画手段として使える。
- Godot：承認された素材の組み立て・動作。FFmpeg等：出力・合成。
- 画像生成・編集・目視確認に必要な機能が使えない場合は BLOCKED_TOOL または NOT_VISUALLY_REVIEWED。プロンプト・不足一覧・構造試作に留め、完成した絵として提出しない。別の利用可能な手段で品質を満たせるならその手段で進める。

## 4. 禁止事項と事故の再発防止

- 基準画像から特徴だけを文章化し、座標や図形による簡易描画で代用すること。
- 生成AIのコンセプト画像と別物のSVGを「同じデザインの設定画」「忠実なパーツ」として提出すること。
- 線・表情・体型・衣装の魅力を犠牲にした代理絵を、CIで緑になった、または数が揃ったという理由で採用すること。
- 鏡像の非対称破綻を隠す、未作画の角度や表情を完成に数える、空の素材を有効パーツと数える、画像未閲覧を目視合格と報告すること。
- 正本へのリンクなし、または比較証拠なしでデザイン審査を依頼すること。
- 作画監督の自己チェックを総監督の承認と混同すること。
- 実装試作は別PR・別パス・TECH_PROTOTYPE と明記する。デザイン審査用の提出物や本番素材の既定参照先から分離し、承認済みの素材に暗黙にフォールバックさせない。

## 5. 必須品質ゲート

提出前に [review_checklist.md](review_checklist.md) を実行し、すべての証拠をPRに載せる。
判定は PASS / FAIL / NOT_RUN / N/A（理由付き）。自己チェックは審査結果ではない。

- **作画QC**：正本との同一性、顔・髪・体格、衣装・配色・小物の左右差、線・影・輪郭、表情・魅力、128pxの識別性、原寸の破綻。実画像の目視が必須。
- **技術QC**：実在・ファイル破損・寸法・アルファ・非空ピクセル・命名・参照、合成位置、ピボット、リグ動作。
- 作画QCと技術QCは別々に判定する。CIは作画QCを代替しない。画像確認不能・正本との重大な不一致・必要な比較証拠不足は作画のブロッカーとし、デザイン審査依頼も正式素材化も不可。Draftの作業報告だけ可。
- 作画自己QC合格後にデザイン審査依頼。総監督による明示的な承認後に実装素材PRへ。素材・絵コンテ・実装確認を揃え、既存のG2最終審査へ進む。
- 完成デザインに重要な変更があれば、差分・理由を示し再承認。承認版、比較対象、成果物コミットを結び付ける。

## 6. PRと引き継ぎ

- デザインと実装素材を別PRにする。デザイン審査は [art_design.md](../../../.github/PULL_REQUEST_TEMPLATE/art_design.md)、素材は [art_assets.md](../../../.github/PULL_REQUEST_TEMPLATE/art_assets.md) を用いる。ルール・試作・不一致の修正記録だけのPRでは、作画提出を装わない。
- 必須情報：Issue、参照コミット、基準画像と版・承認状態、制作方法、画像比較・QCの証拠、未実施事項、差分、レビュー担当、次工程。
- 総監督への審査依頼は [director_review.md](director_review.md) に沿う。
- 通常の作業、修正、検査、Draft PR作成には細かな着手許可を求めない。ただし既存の正式デザイン承認・G2・mainマージ権限は変更しない。

**絵のクオリティが保てなければ、自動化を止めて作画方法を見直す。成果数より、実際の絵を評価する。**
