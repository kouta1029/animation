# PR・成果物レビュー基準 v0.1

目的：技術的に動くことと、**作品として公開できる品質**を区別する。レビュー担当は根拠を示して承認・差戻しする。

## 1. 承認権限とゲート

- 総監督がG0～G5の最終判断を行う。各監督は自分の専門領域の評価と修正提案を担当。
- **PRレビューの承認 ≠ 作品公開のG5承認**。PRがマージされても公開許可は自動で与えられない。
- 確定設定（`docs/decisions.md`）、声・素材の商用利用、外部公開・費用に関わる変更は、総監督の判断を確認する。
- 同一担当による自己承認のみで合格にしない。異なる担当と相互依存するものは関係者の確認を求める。
- `main`への直接push・承認前マージをしない。現在の保護設定は運用ルールと別で、必要ならGitHub側で設定する。

## 2. 重要度・差戻し

| 区分 | 定義 | 対応 |
|---|---|---|
| P0 / Blocker | 権利違反、機密漏洩、ファイル破損、仕様・設定の重大矛盾、音声や字幕が機能しない | **承認不可**。修正と再確認が必要 |
| P1 / Major | キャラ・演技の不一致、画面見切れ、重大なテンポ不良、テスト不足 | 原則差戻し。例外は総監督が理由を記録 |
| P2 / Minor | 軽微な表記、演出の小幅な改善、リファクタ提案 | 承認後の追跡Issueで対応可 |
| Suggestion | 好みや将来の改善案 | ブロックせず根拠付きの提案として残す |

「なんとなく違う」だけで差戻さず、**対象のファイル／カット／セリフID・期待値・現状・修正案**を記載する。

## 3. 共通レビュー項目

- [ ] PRの目的、Issue、対象部門、承認ゲート、参照コミットが明記されている
- [ ] `docs/decisions.md`および`docs/series_bible.md`と矛盾しない
- [ ] 重要な変更に承認がある。仮案・提案を「決定」と記載していない
- [ ] 変更は対象範囲だけで、他PRや担当の成果物を意図せず上書きしていない
- [ ] 成果物のパス、再現・再生の手順、バージョンが明記されている
- [ ] 検証結果が実測に基づく（未実施・未確認を隠していない）
- [ ] 第三者素材・AI音声・BGM・フォントの利用条件が確認されている
- [ ] パスワード・APIキー・個人情報など公開リポジトリに不適切な情報がない
- [ ] 未解決事項と次担当への引き継ぎが記録されている

## 4. 部門別レビュー

### 総監督（G0 / G5）
- タイトルや題材はShortsで分かりやすく、長尺への広がりもあるか。
- 類似作品に依存せず独自のキャラ・世界観があるか。
- 予算・スケジュール・権利・公開目的と矛盾していないか。

### 脚本監督（G1）
- 冒頭の状況が理解でき、人物に目的と選択があるか。
- 起承転結・笑い・オチ・セリフの自然さ、キャラの一貫性。
- SF現象のルールに矛盾がなく、現象が都合よく変わらないか。
- 長尺がShortsの単純な引き延ばしではないか。

### 作画監督（G2）
- 作画は絵のクオリティと基準への忠実度を第一とし、[作画監督ルール](roles/art/agent.md) と[チェックリスト](roles/art/review_checklist.md)を適用する。基準画像との重大な不一致、画像未閲覧、比較証拠欠落は作画の承認ブロッカー。作画QCと技術QCは別判定であり、CI成功を根拠にデザイン承認しない。
- デザイン一次審査は設定画・比較画像で実施。承認後に分割素材PRを提出し、原画との再合成比較を検証する。G2最終承認は従来どおり総監督が判断。
- 3.5～4頭身のデフォルメ画風、シルエット・色の差、スマホでの視認性。
- 同一人物の顔・体格・服装・向きが一貫し、表情に説得力があるか。
- 分割素材の透過・上下関係・ピボット・可動域に破綻がないか。
- **ラフ／試作／承認済み素材**を区別し、未承認デザインを確定と呼ばない。

### 演出監督（G2 / G4）
- セリフの感情と目線・表情・体の動き・カメラが一致しているか。
- 顔アップ、切り返し、リアクション、沈黙の使い方に意図があるか。
- 単純な上下揺れと口パクだけで場面を引き延ばしていないか。
- Shortsの安全領域・長尺での展開・視線誘導が成立しているか。

### 映像監督（G3 / G4）
- 音声・字幕・口形・ショット・素材IDの対応が正しいか。
- MP4が正常に開き、声の明瞭さ、音割れ、無音、同期の問題がないか。
- キャラ・背景・字幕の描画欠けやフレーム落ちがないか。
- Windows等の環境で再現可能か。依存関係と実行コマンドがあるか。

## 5. PRレビューからマージまで

1. PRを読み、変更点と関連Issueの受入条件を確認。
2. 影響を受ける部門にレビューを依頼。必要ならスクリーンショット・試聴・再生結果を求める。
3. P0/P1があれば修正要求。変更後に再チェック。レビュー済みの古いコミットだけで承認しない。
4. 合格したPRには**承認した範囲と証拠**を残し、総監督の決裁に回す。
5. マージ後、Issueを更新し、必要なら`docs/decisions.md`とシリーズバイブルを更新。
6. G5未承認の動画・素材を公開しない。

## 6. レビューコメントの書式

- **判定**：APPROVE / REQUEST_CHANGES / COMMENT
- **重要度**：P0 / P1 / P2 / Suggestion
- **箇所**：ファイルパス、行、カットID、音声ID、動画時刻
- **現状と期待値**：何が起きており、どうすべきか
- **根拠**：仕様、設定、再現手順、キャプチャ、実再生確認
- **次担当／再確認条件**：誰が何を修正すれば通過するか

ドキュメントだけの変更は、リンク・整合性・Markdownの表示を確認。動画・音声の再生検証が不要なら「対象外」と記録する。
