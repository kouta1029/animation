## 00｜基本方針と全体工程

本書は、5担当のAI支援制作チームが、リミテッド2Dの会話劇を品質優先で制作するための実務仕様である。初期資産の構築と各話制作を分離し、GitHubの承認済み成果物を正本とする。音声監督は必要に応じて独立させる。

| 段階 | 主担当 | 完了条件 |
|---|---|---|
| 初期準備 | 全担当 | 世界観・キャラ・声・動作・品質基準の確定 |
| 企画 | 総監督 | G0 企画承認 |
| 脚本 | 脚本監督 | G1 台本承認 |
| 絵コンテ・音声 | 演出監督／音声担当 | G2a 構成確認、G3 音声承認 |
| 作画 | 作画監督 | G2b 素材受入承認 |
| アニメーション | 映像監督 | G4 粗編集承認 |
| 最終仕上げ・公開 | 映像監督／総監督 | G5 公開承認、公開確認 |
| 改善 | 総監督／全担当 | 視聴データ・制作知見を次回へ反映 |

**優先順位：** 作品の面白さ・視覚／音声品質 ＞ 一貫性 ＞ 再現性 ＞ 制作速度。自動テストの成功だけを品質合格の根拠にしない。

**運用上の前提：** 各AIチャットは相互に常時通信しない。担当者は指示を受けて作業し、Issue・PR・確定文書に状況を記録する。自動連携を実装していない限り、次担当の起動は人間または既存の実行基盤が行う。

## 01｜担当者の責任と権限

| 担当 | 責任範囲・担当作業 | 成果物 |
|---|---|---|
| 総監督 | 企画選定、世界観と品質基準、優先順位、工数・予算、差し戻し、ゲート承認、公開判断、分析 | シリーズバイブル、brief、承認記録、改善指示 |
| 脚本監督 | 企画提案、プロット、キャラ設定、セリフ、感情・演技意図、読み、伏線、オチ、必要時の事実確認 | script.md、dialogue.json、脚本意図、確認記録 |
| 演出監督 | シーン分割、絵コンテ、キャラの立ち位置・視線・演技、カメラ、カット尺、間、音響演出、仮映像評価 | storyboard、shot_list、動作指示、タイムライン、演出レビュー |
| 作画監督 | アート設計、キャラ設定画、表情・口・手足・全身差分、背景・小物、原画・中割り、素材の完成検査 | モデルシート、編集原本、透過素材、asset_manifest、プレビュー |
| 映像監督 | リグ・シーン実装、ポーズ遷移、口パク、カメラ、エフェクト、字幕、音声生成・合成、書き出し、技術QA | 制作プロジェクト、動作テスト、MP4、音声データ、検証ログ |
| 音声監督（拡張） | 声の選定、発音・感情監修、セリフ音声生成、BGM・SE、音響ミックス | voice_cast、audio_manifest、WAV、音響QA |

音声監督が未設置の場合は、脚本監督が読み・意味、演出監督が演技、映像監督が生成・同期・ミックス、総監督がG3承認を行う。サムネイルは作画監督が絵素材、映像監督がレイアウト・出力、総監督がタイトルとの整合性を担当する。公開操作は権限を持つ運営者が実施する。

### 責任の境界

- 脚本は「何を話すか」、演出は「どう見せるか」、作画は「どんな絵で表すか」、映像は「どう動かし合成するか」を担当する。
- 他担当の承認済み成果物を無断で変更しない。変更の必要性はIssueで提起する。
- 各担当は自工程の検査・軽微な修正を自律的に進める。重大な設定変更や不合格ゲートは総監督に報告する。

## 02｜シリーズ開始前の共通資産構築

| 順 | 実行担当 → 受取担当 | 作業内容・受け渡し |
|---|---|---|
| P01 | 総監督 → 全員 | コンセプト・世界観・対象視聴者・画角・尺・品質方針を提示 |
| P02 | 脚本 → 総監督／作画／演出 | 人物像、名前、性格、口調、関係性、基本設定を設計 |
| P03 | 作画 → 総監督 | 複数のデザインラフ、画風、色、シルエットを比較し決定 |
| P04 | 作画 → 演出／映像 | 正式モデルシート、方向差分、表情、手足、口、背景、小物を制作 |
| P05 | 演出 → 作画／映像 | 基本ポーズ・演技・カメラ・動作仕様とテスト場面を作成 |
| P06 | 映像 → 作画／演出 | パーツ接続・リグ・動作試験。必要なら作画に不足素材を依頼 |
| P07 | 音声担当 → 総監督／演出 | 同一台本で声・感情・発音を比較。採用声・設定を固定 |
| P08 | 全員 → 総監督 | 実際の会話シーンを試作し、作画・音声・演出・映像品質を検査 |
| P09 | 総監督 → 全員 | 承認した設定、素材、動作、品質基準を共通資産として登録 |

### 作画資産の最低設計範囲

正面・斜め・横・背面等のモデルシート、色・体格比、目・眉・口（閉／母音近似等）、左右の手・腕・足、全身ポーズ、歩行・座る・指差し・ツッコミ等の動作素材。定番背景は自宅、職場、街路など企画に合わせて選定。必要な差分数は実際の演出要件で決定し、不要な素材の量産を避ける。

### 共通資産の受入基準

正式デザインとの並列比較、パーツ再組立て、極端なポーズ時の接続、実際の再生映像、背景との調和を検査する。原本・素材ID・支点・重なり順・解像度・バージョンを記録。正式デザインを固定し、変更は新バージョンで承認する。

## 03｜各話制作 A：企画・脚本（G0／G1）

| STEP | 担当 | 作業・連絡先・成果物 |
|---|---|---|
| 01 | 総監督 | テーマ・狙い・尺・対象形式・登場人物・制約をbriefに記載。G0後、脚本に引継ぎ |
| 02 | 脚本 | プロット、冒頭のフック、事件・展開・オチ、キャラの意図を作成。初稿を総監督へ |
| 03 | 総監督＋脚本 | 面白さ、矛盾、尺、セリフ、オチ、実現可能性を検査。必要に応じて演出・作画・映像に相談し修正。G1後に演出／音声へ |

### 企画ブリーフ（brief.md）

- 話数ID、仮タイトル、狙い、対象視聴者、尺・画角、登場キャラ、世界ルール、テーマ、合格条件、制作制約。
- Shortsは30〜60秒、長尺は初期6〜10分を基本とするが、面白さに応じて調整する。

### 台本の契約（script.md / dialogue.json）

セリフID、話者ID、本文、読み、感情、演技指示、話速・間の指定、場面、動作の意図を記録する。台本段階では時刻は仮値でよい。音声確定後に実測タイムスタンプを登録する。

| セリフID | 話者 | セリフ例 | 演技意図 |
|---|---|---|---|
| L001 | 主人公 | 「今日、なんか変じゃない？」 | 困惑、小声 |
| L002 | 相棒 | 「実は昨日から気づいてた」 | 目をそらす、平然 |
| L003 | 主人公 | 「先に言えよ！」 | 驚き、ツッコミ |

※上記は制作データの例であり、正式な台本ではない。

**G1合格条件：** キャラ設定と矛盾しない、冒頭から結末まで成立、読みと演技指示が明確、必要な素材・技術で制作可能。G1後に台本変更が必要なら影響範囲を確認し、再承認する。

## 04｜各話制作 B：演出・音声（G2a／G3）

| STEP | 担当 | 手順と引継ぎ |
|---|---|---|
| 04 | 演出 | 台本をカットに分解。画角・背景・位置・視線・ポーズ・表情・間・カメラ・SEを仮設計。作画／映像に実現可否を相談 |
| 05 | 音声担当 | セリフIDごとに声を生成。採用声、発音、感情、話速、無音、再生成設定を記録。演出にタイムスタンプを納品 |
| 06 | 総監督／音声担当 | 脚本の意味、演技、話者一致、発音、クリッピング・雑音を確認。必要なセリフのみ再生成しG3承認 |
| 07 | 演出 | 承認音声に合わせカット尺・リップシンク・リアクション・緩急を確定。簡易アニマティックで確認し、G2a承認後に作画／映像へ |

### カット指示書（storyboard / shot_list）

| カットID | 時刻例 | 構図・演技 | 必要素材・音響 |
|---|---|---|---|
| C001 | 0.0–2.5秒 | 二人のミディアム、主人公が困惑 | 室内背景、困惑、L001 |
| C002 | 2.5–5.0秒 | 相棒アップ、視線をそらす | 横目、口差分、L002 |
| C003 | 5.0–7.0秒 | 主人公アップ、腕を振りツッコミ | 専用腕ポーズ、SE、L003 |

時刻は例。実際には採用音声の長さを基準に確定する。カットID・レイヤー・キャラID・素材ID・動作開始終了・表情変化を紐づける。

### 音声仕様

1セリフ1クリップを基本とし、WAVと実測長・タイムスタンプを管理。感情表現はElevenLabs等を候補とし、ローカル音声方式も品質と費用に応じて比較する。採用方式の利用条件・権利を確認する。最終ミックスは48kHzステレオを基本とする。

**G2a：** 構図、演技、必要素材、カット尺、制作可否を演出・作画・総監督が確認する。G2a/G2bは既存G2を分割運用する提案であり、新規の独立承認制度ではない。

## 05｜各話制作 C：作画（G2b）

| STEP | 主担当 | 具体的な作業と成果物 |
|---|---|---|
| 08a | 作画 | 確定絵コンテを参照。カット単位で再利用素材と新規素材を分類。不足一覧を演出／映像に共有 |
| 08b | 作画／演出 | レイアウト、ラフ原画、シルエット・ポーズ確認。演出意図との一致を確認し修正 |
| 09a | 作画 | 正式設定画に沿う線画、彩色、影、原画、中割り、表情・身体・口差分、背景・小物・効果素材を制作 |
| 09b | 作画 | パーツ分離、透過、隠れる部分の補完、支点・座標・前後関係、解像度を設定。編集可能原本を保存 |
| 09c | 作画／映像 | 完成状態への再組立て、目視比較、関節と姿勢の動作試験。不足箇所や画質劣化を修正 |
| 10 | 作画／演出／総監督 | 素材品質・設定一致・演技再現性を受入検査。G2b後、映像に素材・manifest・プレビューを渡す |

### 作画品質の絶対条件

- 承認済みのマスター画像を参照する。同じキャラクターを参照なしで新規生成しない。
- AI生成、ベクター化、コード描画など手段を問わず、正式デザインの輪郭・比率・配色・個性を維持する。
- 左右の手足、関節、指、目、口などの破綻を確認。パーツの回転・差し替えで隙間・ずれ・変形破綻が生じないこと。
- 絵の品質を落とした仮素材を完成素材として扱わない。複雑な動作は専用原画やポーズ差分で補う。
- 静止画、素材一覧、正式画像との並列比較、再組立て画像、動作プレビューを提出する。不合格素材は使わない。

### 素材管理（asset_manifest）

素材ID、種別、キャラ／背景ID、対象カット、元画像・バージョン、原本と出力パス、画像サイズ、透明背景、支点、重なり順、利用条件、検査結果を記録。必要に応じてPNG・SVG・レイヤー付き原本・PNG連番を納品する。

## 06｜各話制作 D：映像・アニメーション（G4）

| STEP | 主担当 | 具体的な作業と引継ぎ |
|---|---|---|
| 11a | 映像 | 承認済み素材をGodot等へ配置。リグ・支点・レイヤー設定と動作クリップを登録 |
| 11b | 映像 | 立ち位置・視線・口パク・瞬き・腕足・体重移動・ポーズ遷移をカット指示に沿って実装 |
| 11c | 映像 → 演出／作画 | 動作試験で不足を特定。演出変更や追加素材をIssueで依頼。代替作画を無断で制作しない |
| 12 | 映像 | カメラ、背景、キャラ、効果、音声、字幕、SE、仮BGMを組み合わせて粗編集MP4を生成 |
| 13 | 全担当 | 脚本＝意味、演出＝間・演技、作画＝絵の一貫性、映像＝技術、総監督＝全体品質を視聴評価 |
| 14 | 該当担当 | カットID・時刻付き指摘を修正して再書き出し。G4合格まで反復し、最終仕上げへ |

### アニメーション実装ルール

リミテッド2Dでは、意味のある動きに資源を集中する。話者の口パクだけでなく、聞き手の視線・表情・リアクション、間、カメラの切り返しを用いる。全カットを機械的な微振動で埋めない。重要なオチや感情の頂点では専用ポーズ・原画を投入する。

### 動画仕様（制作内の基本値）

| 項目 | Shorts | 長尺 |
|---|---|---|
| 解像度 | 1080×1920（9:16） | 1920×1080（16:9） |
| フレームレート | 24または30fps | 24または30fps |
| 最終出力 | MP4／H.264・AACを基本 | MP4／H.264・AACを基本 |
| 音声 | 48kHz、ステレオ | 48kHz、ステレオ |

**G4合格条件：** 意図した演技、画面構成、会話テンポ、音声同期が再生映像で成立する。未解決の重大な品質問題がない。技術テストと実際の動画視聴の両方を行う。

## 07｜各話制作 E：仕上げ・最終承認・公開

| STEP | 担当 | 手順と引継ぎ |
|---|---|---|
| 15 | 映像／作画／総監督 | 音声ミックス、字幕、安全領域、色、映像書き出し。サムネ素材・デザイン、タイトル、説明文を作成 |
| 16 | 総監督 | G5最終審査。実ファイルを通し視聴し、品質、権利、公開設定、制作データを確認。不合格なら差し戻す |
| 17 | 運営者／総監督 | 承認済み動画・メタデータを登録。公開後、再生・字幕・公開URLを確認し記録 |
| 18 | 総監督／全担当 | 公開後48時間・7日・28日のデータを確認し、次の脚本・演出・作画・映像に改善Issueを登録 |

### 最終QAチェック

| 分野 | 検査項目 |
|---|---|
| 脚本 | 矛盾、セリフ抜け、オチ、キャラ設定、事実確認が必要な箇所 |
| 演出 | 会話の間、視線、リアクション、構図、冒頭の引き、テンポ |
| 作画 | 正式デザイン、輪郭・色、手足、接続、表情差分、背景との調和 |
| 映像 | 口パク・同期、黒／欠損フレーム、ちらつき、解像度、FPS、再生互換性 |
| 音声 | 読み、感情、雑音、音量差、BGM・SEの聞こえ方、クリッピング |
| 公開 | 字幕安全領域、サムネ、タイトル、素材・音声・音楽の権利、必要な表示・設定 |

重大な不具合が残る場合は公開しない。権利・利用条件は公開前に実際の契約や規約を確認する。

### 公開後の評価

クリック率（取得できる形式）、視聴維持率、離脱点、視聴時間、登録転換、コメント、制作時間を記録する。脚本・演出・画面・音声のどこが弱いか仮説を立て、次回の改善目標にする。成果物を保管し、再利用可能な素材を共通資産に追加する。

## 08｜承認ゲートと差し戻しルール

| ゲート | 承認者 | 合格に必要な成果物 | 不合格時の戻り先 |
|---|---|---|---|
| G0 企画 | 総監督 | brief、目的・制約 | 企画 |
| G1 脚本 | 総監督＋脚本 | 台本、セリフ一覧 | 脚本 |
| G2a 絵コンテ | 演出＋作画＋総監督 | 絵コンテ、素材要求、実装可否 | 演出（必要なら脚本） |
| G3 音声 | 総監督／音声担当 | 採用音声、時刻、試聴記録 | 音声（必要なら脚本・演出） |
| G2b 素材 | 演出＋作画＋総監督 | 素材、manifest、目視・動作検査 | 作画または演出 |
| G4 粗編集 | 演出＋映像＋総監督 | 粗編集動画、各担当レビュー | 該当担当 |
| G5 公開 | 総監督 | 最終MP4、QA、権利、公開情報 | 該当担当 |

G2aは仮段階の検討を音声制作と並走できる。確定版はG3の実測尺を反映し、G2bへ進む。G2bとG3両方の承認を映像本制作の条件とする。

### 不具合の振り分け

| 問題 | 修正責任者 | 再確認 |
|---|---|---|
| 物語やセリフの不整合 | 脚本 | 総監督、演出 |
| 構図、演技、カット尺 | 演出 | 総監督、映像 |
| 顔・体型・手足・背景の破綻 | 作画 | 演出、総監督 |
| 関節の隙間、動作の崩れ | 映像（素材が原因なら作画） | 作画、演出 |
| 発音・感情・音質 | 音声担当 | 演出、総監督 |
| 字幕・合成・音ズレ | 映像 | 演出、総監督 |

重大度P0＝公開・進行停止、P1＝ゲート承認前に修正、P2＝品質への影響を評価し修正または次回へ。修正箇所の影響を追跡し、前工程変更時は依存する承認を再実施する。未解決のP0/P1を抱えたまま合格扱いにしない。

## 10｜担当間の具体的な連絡例

例題：『全員が嘘をつけなくなった日』（仮企画）。以下は実際の運用を想定した引き継ぎ例であり、制作済みの事実ではない。

| 順 | 送信 → 受信 | 連絡内容 |
|---|---|---|
| 1 | 総監督 → 脚本 | G0承認。冒頭で異常を提示し、日常の会話と意外なオチを作る |
| 2 | 脚本 → 総監督 | 初稿・プロット・セリフIDを提出。キャラの動機とオチを確認依頼 |
| 3 | 総監督 → 脚本 | オチを修正。G1承認後、演出・音声へ共有 |
| 4 | 演出 → 音声／作画 | カットC003は驚きとツッコミ。発話後に間、専用腕ポーズが必要 |
| 5 | 音声 → 演出 | L003採用音声、実測尺と発話位置を提出。G3承認後に絵コンテ更新 |
| 6 | 演出 → 作画／映像 | G2a承認済みのカット表・演技仕様。C003の後ずさり・腕ポーズを制作依頼 |
| 7 | 作画 → 演出 | ラフを提出。意図確認後に清書し、公式設定との差分・動作試験を実施 |
| 8 | 作画 → 映像 | G2b承認。パーツ、専用原画、支点、asset_manifestを納品 |

### 初回運用の完了条件

総監督は本書の採用可否を判断し、各担当の `AGENTS.md` と品質基準・PRテンプレートに反映する。初回の30〜60秒パイロットで全工程を一度通し、受け渡し漏れ・画の崩れ・同期・実工数を検証する。改善点を本書の改訂版へ反映する。

**改訂履歴：** v1.0（2026-11-22） 初版。既存設計書のG0〜G5を維持し、役割・工程・G2分割案・品質検査・引き継ぎを具体化。
